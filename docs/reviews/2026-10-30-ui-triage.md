# UI triage (2026-10-30)

Lens for every element: why does it exist, does the user need it, is it in the right place,
is there a simpler alternative, would removing it make things clearer?

## Principles (apply everywhere)
- **Less text.** No sentences explaining what users already know or that aren't about the
  current page (e.g. "Tasks the server has accepted. Closing the launcher doesn't cancel them.").
  One short line max under a heading; prefer none.
- **Intent-aware confirmations.** No confirm dialog when the user dug through a menu to reach the
  action. For destructive actions that haven't started yet, act immediately with an **Undo**
  toast that cancels before the permanent step. Keep a confirm only for irreversible + one-click.
- **Design for the space.** Purpose-built compact components over generic stacked panels.
  Reference: the instance modpack version card (one row: current version, source, details,
  update state + one dropdown to switch).
- **Consistent width.** Pages use the same content width/alignment rules.
- **No artificial expiry.** Reviews/plans don't show countdowns; if a plan is stale at apply,
  re-plan transparently and only surface real changes.

## M6: modpack install review (design brief)
- Never navigate away from the review.
- Header = pack icon + name + one-line description + source badge (from resource metadata);
  no separate subtitle.
- Software/version switching is **part of the installation**, not a separate flow or redirect:
  when the pack needs a different server software or Minecraft version, the review shows one
  line (e.g. "Switches the server to Fabric 1.21.4") and the user ticks a single acknowledgement
  ("This changes the server's software and may break existing worlds/plugins") before Install.
  Applying performs the switch and the pack install together.
- Minimal text; backup offered as a small inline checkbox/option, not a prominent button.
- Changes summary compact (counts + expandable lists), conflicts inline.
